\subsection{Automated Diagnostic Convergence (Scenarios 3, 3-Stratified, 4a, and 4b)}
To evaluate diagnostic efficiency ($MTTDiag$, Hypothesis $H_{1,1}$) and diagnostic accuracy ($Acc$, Hypothesis $H_{1,2}$) without human operator bias or learning effects, fault injection and root-cause localization were executed autonomously by four deterministic Root Cause Analysis (RCA) orchestration scripts (\texttt{run-scenario3-trials.py}, \texttt{run-scenario3-stratified-trials.py}, \texttt{run-scenario4-trials.py}, and \texttt{run-scenario4-optimized-trials.py}). In accordance with \textbf{ADR-0001} and \textbf{ADR-0002}, all diagnostic campaigns shared an identical, deterministically seeded factorial schedule (\texttt{RANDOM\_SEED = 42}) across $N=30$ paired trials---comprising $11$ \texttt{cpu-stress}, $10$ \texttt{network-delay}, and $9$ \texttt{pod-kill} perturbations distributed across $\mathcal{P}_{\text{target}} = \{\texttt{cart}, \texttt{currency}, \texttt{payment}, \texttt{shipping}\}$---while keeping the diagnostic functions strictly blind to the injected ground truth:

\begin{enumerate}
    \item \textbf{Cooldown, Pod-Reset Snapshot, and State Priming:} Prior to each trial, the orchestrator purged residual Chaos Mesh objects (clearing stuck Kubernetes finalizers when required), verified deployment readiness, and enforced a mandatory $20\,\text{s}$ stabilization cooldown. To prevent pre-existing telemetry from polluting post-injection inference, the observability harnesses cached active trace IDs, log signatures, and pre-injection container start/restart counters prior to $T_0$.
    
    \item \textbf{Paired Pod-Scoped Perturbation ($T_0$):} For each trial $i \in \{1, \dots, 30\}$, the orchestrator resolved the active pod instance of $\text{target}_i$ (\textbf{ADR-0004}), instantiated the corresponding Chaos Mesh CRD (\texttt{StressChaos}, \texttt{PodChaos}, or \texttt{NetworkChaos} with \texttt{direction: to}), and recorded the authoritative UTC timestamp $T_0$.
    
    \item \textbf{Deterministic Algorithmic Polling ($3\,\text{s}$ initial wait, $4\,\text{s}$ cadence):}
    \begin{itemize}
        \item \textit{Scenario 3 and Scenario 3-Stratified (Vanilla CLI Baseline):} The engine executed breadth-first sequential scraping of native Kubernetes container logs (\texttt{kubectl logs --since-time=}$T_0$) across the call-graph hierarchy, applying regex signature matching to detect explicit exception propagation. Executing both the primary baseline (\texttt{scenario3\_diagnostic\_trials.csv}) and an independent stratified replication (\texttt{scenario3\_diagnostic\_trials\_stratified.csv}) verified the test-retest stability of the Vanilla control group.
        
        \item \textit{Scenario 4a (Monomodal Distributed Tracing RCA):} The engine queried the Grafana Tempo REST API for anomalous traces ($\ge 1500\,\text{ms}$ or error status flags) generated after $T_0$ and attributed the fault to spans exhibiting explicit error status codes or the maximum total (inclusive) span duration, testing whether single-pillar tracing without self-time decomposition suffices for root-cause isolation.
        
        \item \textit{Scenario 4b (PANOPTES Multimodal Correlated RCA):} Operationalizing Control Principles \texttt{CP1} and \texttt{CP2} strictly over HTTP APIs without \texttt{kubectl} fallbacks (\textbf{ADR-0002}), the optimized engine combined three correlated diagnostic pathways: (i)~PromQL queries over Prometheus (\texttt{container\_cpu\_usage\_seconds\_total} saturation rates and \texttt{kube\_pod\_start\_time} / restart deltas); (ii)~LogQL queries over Grafana Loki to capture container termination (\texttt{SIGTERM}, socket resets) and pivot via extracted \texttt{traceID}s; and (iii)~Grafana Tempo OTLP trace tree traversal using \textit{exclusive span self-time decomposition} ($T_{\text{self}} = T_{\text{span}} - \sum T_{\text{children}}$) and L4/L7 peer attribution (\texttt{server.address}, \texttt{net.peer.name}, \texttt{rpc.service}) to isolate the downstream bottleneck.
    \end{itemize}
    
    \item \textbf{Statistical Right-Censoring and Audit Persistence:} If an RCA engine failed to converge within $T_{\text{max}} = 300\,\text{s}$, the iteration was terminated, scored as $Acc = 0$, and right-censored at $MTTDiag = 300.0\,\text{s}$ ($\text{censored} = \text{True}$). Conversely, premature convergence on a non-injected service was recorded with its exact elapsed time, $Acc = 0$, and $\text{censored} = \text{False}$. In Scenario~4b, every diagnostic verdict was additionally logged with its primary detection modality and cryptographic trace/metric evidence identifier in \texttt{scenario4b\_evidence\_audit.jsonl}.
\end{enumerate}
