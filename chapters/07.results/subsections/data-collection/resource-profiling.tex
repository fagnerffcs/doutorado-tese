\subsection{Steady-State Resource Profiling (Scenarios 1 and 2)}
To evaluate the static computational footprint of the telemetry infrastructure (Hypothesis $H_{1,3}$), the script \texttt{run-scenario1-baseline.py} (and its Scenario~2 counterpart) periodically sampled the cluster state. The script executed native \texttt{kubectl top pods} commands every 5 seconds over a continuous 150-second window, parsing the raw \texttt{stdout} stream. 

Computational values were algorithmically normalized: CPU utilization was converted to uniform millicore integer constraints (e.g., parsing \texttt{15m} or nano-cores to strictly bound \text{mCPU}), while resident memory allocations were standardized to Mebibytes (\text{MiB}). The script aggregated the metrics per namespace (\texttt{otel-demo} for the application workload and \texttt{monitoring} for the PANOPTES stack), appending the time-series tuples directly to persistent CSV artifacts (\texttt{scenario1\_workload\_baseline.csv} and \texttt{scenario2\_overhead\_panoptes.csv}).
