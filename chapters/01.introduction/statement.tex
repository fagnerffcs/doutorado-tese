\section{Thesis Statement and Contributions}
\label{sec:statement}

\textbf{Thesis Statement:} \textit{A vendor-agnostic, open-source reference architecture that enforces semantic correlation across metrics, logs, and distributed traces via standardized OpenTelemetry schemas and exclusive span self-time decomposition significantly reduces the Mean Time to Diagnose ($MTTDiag$) and significantly increases Diagnostic Accuracy ($Acc$) during latent microservice faults in Kubernetes compared to native platform inspection mechanisms, while maintaining its dynamic CPU processing overhead within a bounded operational envelope.}

The primary goal of this research is to advance the state of the art in cloud-native observability by transitioning from ad-hoc tool chaining to a formalized architectural model. To this end, the core contributions of this thesis are defined as follows:

\begin{itemize}
    \item \textbf{The PANOPTES Reference Architecture:} A formalized, vendor-agnostic architectural blueprint for Kubernetes observability. It structurally maps how metrics, logs, and traces must be generated, collected, and semantically correlated to achieve system observability in accordance with control theory principles (\texttt{CP1} and \texttt{CP2}).
    
    \item \textbf{An Open-Source Implementation Artifact:} A concrete instantiation of the PANOPTES architecture using Infrastructure as Code (K3d/Multipass cluster provisioning, Ansible playbooks, and Helm charts), governed by Markdown Architectural Decision Records (\textbf{ADR-0001}--\textbf{ADR-0006}). This artifact operationalizes OpenTelemetry, Prometheus, Grafana Loki, and Grafana Tempo in a reproducible, deterministic environment, providing a ready-to-use blueprint for practitioners and researchers.
    
    \item \textbf{Empirical Evidence via Chaos Engineering and Automated RCA:} A rigorous quantitative evaluation of the proposed architecture under a paired, stratified $2\times2$ factorial experiment. Through controlled fault injection campaigns (Chaos Mesh), this study provides empirical data on the resource footprint introduced by the observability stack ($H_{1,3}$) and its statistically validated impact on the Mean Time to Diagnose ($MTTDiag$, $H_{1,1}$) and Diagnostic Accuracy ($Acc$, $H_{1,2}$), establishing a scientific benchmark for future comparisons.

    \item \textbf{The Observability Maturity Model (OMM):} A conceptual framework derived from a Rapid Review of the state of the art, categorizing the evolutionary stages of telemetry management in cloud-native environments across five capability levels and empirically validating its target correlated state (Level~4).
\end{itemize}
