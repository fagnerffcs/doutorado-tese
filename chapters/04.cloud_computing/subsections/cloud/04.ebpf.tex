\subsection{eBPF as the Low-Level Observability Substrate}
\label{subsec:ebpf-foundation}

The fundamental limitation of purely application-level observability (OSI Layer~7) resides in its detachment from the underlying operating system kernel and network transport mechanics. To address this ``Layer Visibility Gap'' at the conceptual reference architecture level, the PANOPTES framework incorporates the Extended Berkeley Packet Filter (eBPF) within its kernel-level instrumentation tier (and its OMM Level~4 $\rightarrow$ Level~5 strategic roadmap). eBPF is a Linux kernel technology that permits the execution of sandboxed bytecode directly within the kernel, dynamically observing operating system events without requiring application source-code modifications or custom kernel modules \cite{rice_2023}.

In cloud-native ecosystems, containers are isolated Linux processes sharing a single host kernel \cite{salazar2022security}. Consequently, an eBPF program attached to kernel hooks possesses visibility over containerized workloads operating on that node \cite{rice_2023, salazar2022security}. To guarantee system stability and safety, eBPF relies on an in-kernel verifier that performs static analysis on the bytecode, ensuring memory safety, preventing infinite loops, and validating pointer dereferences prior to execution \cite{calavera2019linux}. Once verified, the bytecode is translated by a Just-In-Time (JIT) compiler into native machine instructions, enabling high-performance telemetry extraction with minimal context-switching overhead \cite{rice_2023, calavera2019linux}.

The strategic value of eBPF in cloud-native observability lies in bridging lower-layer network mechanics (Layer~4 socket state, TCP retransmissions, and round-trip latency pre-NAT) with higher-layer Kubernetes identities (pod names and namespaces) \cite{salazar2022security, shekhar2023ultimate}. By hooking into kernel \textit{kprobes}, \textit{tracepoints}, and socket-level events, eBPF complements application-level instrumentation \cite{calavera2019linux}. While full eBPF service-mesh dataplanes (e.g., Cilium/Hubble) represent the non-intrusive kernel tier of the PANOPTES conceptual blueprint (Figure~\ref{fig:research-roadmap}), within our controlled K3d experimental testbed (Chapter~\ref{chap:experiment-implementation}) cross-layer L4/L7 fault attribution---such as isolating the $2000\,\text{ms}$ kernel \texttt{tc-netem} socket delay injected via Chaos Mesh---is operationalized deterministically by combining Linux kernel \texttt{cgroup} metrics with OpenTelemetry L4/L7 transport attributes (\texttt{server.address}, \texttt{net.peer.name}, and \texttt{rpc.service}) and exclusive span self-time decomposition ($T_{\text{self}}$), avoiding CNI dataplane interference during Chaos Mesh network manipulation.
