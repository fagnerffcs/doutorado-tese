\subsection{Alignment between Technical Choices and Secondary Research Questions}
\label{subsec:align-tech-rqs}

The PANOPTES reference architecture is not an arbitrary collection of open-source tools; each component was deliberately selected to provide the empirical evidence required to answer the Secondary Research Questions (\textbf{SRQ1}--\textbf{SRQ4}) posed in Chapter~\ref{chap:intro}:

\begin{itemize}
    \item \textbf{Addressing SRQ1 (Minimum Architectural Requirements):} To define the minimum requirements for a cohesive observability layer, the architecture adopts the \textit{OpenTelemetry} (OTel) standard for telemetry generation and collection. This addresses \textbf{SRQ1} by establishing a vendor-agnostic instrumentation layer that ensures schema parity across metrics, logs, and traces, defining the core components (DaemonSet Collectors, Specialized Storage Backends, and Correlation Interfaces) required to achieve full observability in Kubernetes without vendor lock-in.

    \item \textbf{Addressing SRQ2 (Semantic Integration vs.\ Resource Burden):} The integration of Prometheus, Grafana Loki, and Grafana Tempo directly targets \textbf{SRQ2}. The primary architectural challenge is ensuring semantic integration---the ability to correlate signals across modalities---without overwhelming cluster resources ($H_{1,3}$). By enforcing a shared OpenTelemetry and Kubernetes label taxonomy (e.g., \texttt{namespace}, \texttt{pod}, \texttt{service.name}, and \texttt{trace\_id}), the architecture enables cross-pillar correlation across metrics, traces, and logs while avoiding expensive full-text log indexing (via Loki's label-only chunk model) and heavy secondary trace indexing (via Tempo's object-block storage).

    \item \textbf{Addressing SRQ3 (Effectiveness of Fault Detection and Diagnosis):} The effectiveness of fault diagnosis is empirically validated by comparing the native Kubernetes inspection mechanisms (the Vanilla Baseline) against the PANOPTES architecture under Chaos Mesh fault injection. Combining Prometheus saturation/restart metrics, Loki exception streams, and Tempo distributed trace self-time decomposition ($T_{\text{self}}$) enables deterministic localization of root causes in request flows that remain invisible to metric-only or CLI-only workflows. Under this comparative design, we evaluate both the \textit{Mean Time to Diagnose ($MTTDiag$, $H_{1,1}$)} and \textit{Diagnostic Accuracy ($Acc$, $H_{1,2}$)}, verifying whether the resource footprint of PANOPTES ($H_{1,3}$) is a justifiable trade-off for superior diagnostic precision.

    \item \textbf{Addressing SRQ4 (Evolutionary Stages and Maturity Gaps):} Finally, by implementing and evaluating this layered architecture across Vanilla CLI (Level~2), Monomodal Tracing (Level~3), and PANOPTES Multimodal Correlation (Level~4), we empirically validate the progression criteria of the Observability Maturity Model (OMM) proposed in Chapter~\ref{chap:related-work}, demonstrating how PANOPTES bridges the cross-signal correlation gap identified in current open-source deployments.
\end{itemize}
