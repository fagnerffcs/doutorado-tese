\section{The Analytical Shift: From Monitoring to Observability}
\label{sec:analytical-shift}

Understanding the four telemetry modalities ($M, L, T, E$) requires establishing a rigorous theoretical and operational boundary between traditional \textit{monitoring} and modern \textit{observability}. Although frequently conflated in industry parlance, they represent fundamentally distinct paradigms along the system control loop, as illustrated in Figure~\ref{fig:obs-vs-mon}.

Monitoring is a reactive verification paradigm that tracks a system's health using predefined sets of metrics and static threshold rules to detect anticipated failure modes (the ``known unknowns''). It functions essentially as an alarm signaling that a symptom has breached a Service Level Indicator (SLI). However, in dynamic, microservice-oriented architectures, static monitoring overlooks emergent, non-linear interaction faults because those failure modes do not match any pre-configured alert signature.

Observability, in contrast, is the deductive analytical capability to interrogate the system's external outputs to determine \textit{where} and \textit{why} an arbitrary failure occurred, particularly for unforeseen cascading anomalies (the ``unknown unknowns''). While monitoring alerts the operator that a subsystem is degraded, observability provides the structural and semantic means to infer the broken internal state, fulfilling Kalman's original premise of state reconstructibility as a prerequisite for system control \cite{kalman_1959}. Consequently, monitoring is a necessary subset of observability, but relying exclusively on monitoring in cloud-native environments leaves operators blind during complex distributed incidents.

Evaluating the current cloud-native landscape through Kalman's theoretical lens exposes a pervasive architectural gap. Existing open-source tools have vastly improved the extraction of raw ``external outputs'' (e.g., time-series scraping via Prometheus or span collection via Jaeger), yet most deployments fall short of true observability. As demonstrated in the literature, merely maintaining isolated dashboards for metrics, logs, and traces produces an advanced monitoring setup rather than an observable system \cite{usman_2022, hartikainen_2024}. Because these siloed tools lack native semantic correlation, they fail to reconstruct the internal causal state of the application without tedious, manual human pivoting.

This cognitive burden during Root Cause Analysis (RCA), exacerbated by cloud-native ephemerality and the volume of disjointed multimodal data, is precisely where ad-hoc implementations fail to satisfy Kalman's duality requirement \cite{han_2024, gomes_2025, li_2024}. As highlighted by \citeonline{han_2024}, the absence of a holistic architectural framework to correlate heterogeneous telemetry limits diagnostic generalizability and inflates troubleshooting latency. This reinforces the need for a unified reference architecture that structurally binds these disjointed signals into a single causal graph.
