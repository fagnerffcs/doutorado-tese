\section{Infrastructure as Code Strategy}
\label{sec:iac-strategy}

While the cluster provisioning scripts (Multipass in Appendix~\ref{app:multipass-commands} and K3d in Appendix~\ref{appendix:c}) instantiate the 3-node Kubernetes substrate with strict hardware quotas, the configuration of the software stack is managed declaratively by Ansible and Helm. We adopted a role-based architectural pattern that enables deterministic switching between the Vanilla and PANOPTES scenarios via configuration flags.

The Ansible playbooks for the Vanilla baseline (\texttt{deploy-vanilla.yml}) and the PANOPTES architecture (\texttt{deploy-panoptes.yml}) are presented in Appendix~\ref{appendix:b}. The provisioning pipeline follows a deterministic sequence, as illustrated in Listing~\ref{code:playbook}.
