\section{Experiment Execution Procedure}
\label{sec:execution-procedure}

To ensure statistical reliability and eliminate operator and learning biases, the experimental execution follows a strictly automated and repeatable protocol across both the resource overhead campaigns (Scenarios~1 and~2) and the fault-diagnosis campaigns (Scenarios~3, 4a, and~4b, with $N=30$ paired trials per scenario) \cite{wohlin_2012}.

For the resource overhead evaluation ($H_{1b}$), the profiler scripts (\texttt{run-scenario1-baseline.py} and \texttt{run-scenario2-overhead.py}) collect $N=30$ observations at a strict $16\,\text{s}$ sampling interval over a $480\,\text{s}$ steady-state window. As documented in \textbf{ADR-0003}, sampling every $16\,\text{s}$ strictly exceeds the default $15\,\text{s}$ K3s \texttt{metrics-server} kubelet scraping resolution, guaranteeing statistically independent observations and preventing step-function pseudoreplication.

For the diagnostic effectiveness evaluation ($H_{1a}$), rather than relying on human operators navigating terminal prompts or graphical interfaces, both the baseline (Scenario~3) and experimental (Scenarios~4a and~4b) diagnostic workflows are executed autonomously by deterministic Root Cause Analysis (RCA) engines \cite{wang_2024, barata_2026}. Each trial follows four sequential phases:

\begin{enumerate}
    \item \textbf{State Restoration, Health Validation, and Warm-up:} Prior to each iteration, the orchestrator validates live telemetry and Chaos Mesh control-plane readiness, removes any previously injected chaos resources (stripping stuck finalizers if termination exceeds the timeout), and verifies pod readiness across the \texttt{otel-demo} namespace. A mandatory 20-second stabilization cooldown is enforced to purge pending TCP connections, clear transient kernel queues, and stabilize CPU, memory, and network I/O to steady-state levels \cite{jain_1991, georges_2007}.
    
    \item \textbf{Steady-State Load Generation:} The polyglot Astronomy Shop workload operates under continuous synthetic traffic driven by its native Locust-based \textit{loadgenerator} microservice. User sessions actively traverse the inter-service call graph (product catalog queries, cart mutations, currency conversions, shipping quotes, and checkout sequences) prior to perturbation.
    
    \item \textbf{Paired, Stratified Blind Fault Injection ($T_0$):} Faults are injected programmatically via Chaos Mesh using a deterministic, balanced factorial schedule seeded with \texttt{RANDOM\_SEED = 42} (\textbf{ADR-0001}). Across the $N=30$ trials, the schedule guarantees an exact stratification of 10 \texttt{network-delay}, 10 \texttt{pod-kill}, and 10 \texttt{cpu-stress} perturbations distributed across the critical transaction target pool ($\mathcal{P}_{\text{target}} = \{\texttt{payment}, \texttt{cart}, \texttt{shipping}, \texttt{currency}\}$). Because the exact same seeded permutation is executed across Scenarios~3, 4a, and~4b, every Trial~$i$ shares an identical $(\text{target}_i, \text{chaos\_type}_i)$ pair while keeping the diagnostic algorithm completely blind to the injected ground truth (\textbf{ADR-0002}). If a transient Kubernetes API admission error prevents fault creation prior to $T_0$, the orchestrator cleans up and repeats the trial index without polluting the dataset with false right-censored entries (\textbf{ADR-0004}). The exact UTC RFC3339 timestamp immediately following successful fault creation is recorded as $T_0$.
    
    \item \textbf{Algorithmic Diagnosis and Latency Extraction ($T_{\text{diag}}$):} Following an identical 3-second initial fault-propagation window, each diagnostic engine initiates periodic polling every $4\,\text{s}$ (\textbf{ADR-0001}) to isolate the root-cause microservice:
    \begin{itemize}
        \item \textbf{Vanilla Kubernetes CLI Baseline (Scenario~3 --- \texttt{run-scenario3-trials.py} \& \texttt{run-scenario3-stratified-trials.py}):} The engine interacts exclusively with native Kubernetes CLI endpoints, executing container restart-delta and pod-status inspection (\texttt{kubectl get pods}), breadth-first log scraping constrained by temporal \texttt{--since-time=}$T_0$ filters (\texttt{kubectl logs}), and resource saturation polling via the \texttt{metrics-server} API (\texttt{kubectl top pods}) \cite{wang_2024}.
        \item \textbf{Standard Distributed Tracing RCA (Scenario~4a --- \texttt{run-scenario4-trials.py}):} Evaluates a monomodal trace-only baseline by querying Grafana Tempo HTTP endpoints for anomalous traces and attributing anomalies to spans with error status codes or the longest total span duration.
        \item \textbf{PANOPTES Multimodal Correlated RCA (Scenario~4b --- \texttt{run-scenario4-optimized-trials.py}):} Queries the unified PANOPTES telemetry backends strictly via HTTP APIs without any \texttt{kubectl} fallback (\textbf{ADR-0002}). It correlates: (i) Prometheus PromQL queries for container restart deltas, cgroup CPU saturation, and $p95$ span latency spikes; (ii) Loki LogQL queries for high-severity exception and crash streams; and (iii) Tempo OTLP trace topology analysis using \textit{exclusive span self-time decomposition} ($T_{\text{self}} = T_{\text{span}} - \sum T_{\text{children}}$) and L4/L7 peer attribution (\texttt{server.address}, \texttt{net.peer.name}, \texttt{rpc.service}) to pinpoint the exact downstream bottleneck without upstream cascading bias \cite{barata_2026}.
    \end{itemize}
\end{enumerate}

The Mean Time to Diagnose ($MTTDiag$) for each iteration is recorded as the wall-clock execution latency between fault injection and algorithmic convergence:
\begin{equation}
    MTTDiag = T_{\text{diag}} - T_0
\end{equation}
If the diagnostic engine fails to converge on a candidate component within the operational ceiling of $300\,\text{s}$ ($5\,\text{min}$), the iteration is right-censored at $300\,\text{s}$ ($Acc = 0$, $\text{censored} = \text{True}$). Conversely, if the engine converges prematurely on an incorrect upstream or collateral service, the actual elapsed convergence time is preserved with $Acc = 0$ and $\text{censored} = \text{False}$.
